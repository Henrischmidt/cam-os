## 3. PATTERNS

**Queue starvation is now the primary bottleneck.**
Claude idles correctly when `NEXT UP` is empty — but that caused 2 days with zero output this week (May 19–20 and May 23–24). Both gaps were pure queue lag, not technical blockers. The fix is trivial: Cam drops one line in `BUILD_QUEUE.md` and the session fires. For post-v1 work, consider keeping a lightweight backlog in the QUEUED section at all times.

**Scope expansion is healthy but undisciplined.**
Post-v1 features (day/night mode, Work/Focus tabs, meds tracker) arrived as ad-hoc requests rather than formal phase definitions. This is fine for velocity, but it creates two problems: (1) no acceptance criteria to close against, and (2) features can land on branches without PRs (see meds tracker). A lightweight "Phase 8: post-launch features" block in BUILD_QUEUE.md would give Claude a home for these without needing a full spec section.

**PR supersession happened once.**
PR #16 (icons + notifications) was opened and immediately superseded by the more comprehensive PR #17. This indicates Claude occasionally opens a PR slightly ahead of discovering the full scope of a feature cluster. No material harm — PR #16 was just closed — but it's a signal that the polish/feature work benefits from a brief description upfront before Claude starts.

**Unmerged branch debt accumulating.**
The meds tracker commit sits on `claude/polish-day-night-cards` with no PR opened. This is the first time a completed feature has gone without a PR in the entire build. The branch is now 2 days old with no review path. Left alone, it will either get lost or cause a rebase conflict when the next branch diverges.

**Multi-phase sessions are possible when spec is clear.**
May 18 saw Phases 4, 6, and 7 all merged in a single day alongside the timer stopwatch feature. This confirms the earlier pattern: when the acceptance criteria are precise, Claude can run multiple phases back-to-back without breaking the PR-per-phase discipline.
